### Important System-Wide Requirement

The system must operate as a **centralized management platform**.

Avoid designing each module as an isolated system.

For example, if a trainee's status changes in Parade State, determine whether that information should affect:

* Daily strength
* Attendance
* Course records
* Examination eligibility
* Reports
* Dashboard statistics

Similarly, if a trainee is registered for a course, determine which other modules should automatically be able to access that information.

### Existing System Rules

Preserve these important requirements from the existing system:

* The system uses role-based access control.
* The Executive Dashboard is the main system landing area.
* The **Back to Home Portal** button must return the user to the Executive Dashboard.
* When a user selects a module, the system must verify the user's authenticated role and permissions.
* Administrators have broader system access.
* Instructors should only access information relevant to their assigned courses/responsibilities.
* Officer IC responsibilities must be maintained separately from Instructor responsibilities.
* Instructor assignment is associated with course registration/batch management.
* Parade State is submitted trade-by-trade.
* Officer IC is selected based on the appropriate appointment.
* Instructor approval is required where defined by the existing workflow.
* Only approved Parade State information should affect the official daily strength.
* Night Parade / Evening Roll Call must support status changes independently from the morning parade state and must provide a clear **Save/Submit** mechanism.
* Trainee status changes should be properly persisted in the database and reflected in relevant modules.
* Accommodation management should handle billet/room-related information and bed allocation without unnecessarily introducing a separate room-management concept.
* Academic module landing should initially display dashboard/summary tiles rather than immediately displaying a large record list.
* Course, batch, trainee, instructor, attendance, examination and academic information should be interconnected.
* Course calendar should prevent duplicate/conflicting events where applicable.
* Lesson plans should support document upload and preview.
* Course completion/passed-out status should be handled according to course dates and academic results.
* Reports should use actual system data rather than placeholder information.
* Important user actions and changes should be auditable.
